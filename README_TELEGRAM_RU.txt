OBBY SMASH RUSH — Telegram Mini App 0.7.5-tg

ГОТОВО
Это отдельный статический Web-билд для Telegram, а также обычного браузера.
В нём подключён официальный Telegram WebApp JavaScript API. Учтены стабильная высота окна, системные и Telegram-отступы, DPI и смена ориентации.
Кнопка «Назад» Telegram закрывает открытое игровое меню. При сворачивании запрашивается немедленное сохранение, игра и обе аудиошины ставятся на паузу. При возвращении учитываются пользовательские настройки звука.
Использован однопоточный экспорт Godot 4.5.1 Compatibility/WebGL2. canvas_items и expand уже настроены; специальный сервер с COOP/COEP для этой сборки не требуется.

ЧТО ДЕЛАТЬ ДАЛЬШЕ
1. Распакуй Web ZIP в отдельную папку: index.html, index.js, index.wasm и index.pck должны остаться рядом.
2. Размести эти файлы на статическом HTTPS-хостинге. Сначала добейся запуска по обычной HTTPS-ссылке в браузере.
3. В @BotFather создай бота командой /newbot и мини-приложение командой /newapp. Следуй его вопросам; в поле URL вставь рабочую HTTPS-ссылку на игру, short name можно выбрать obby. Также можно настроить кнопку меню бота через /setmenubutton.
4. Проверь ссылку вида https://t.me/ИМЯ_БОТА/obby в Telegram на телефоне и ПК: запуск, звук после PLAY, тап, забег, улучшения, скин, поворот, «Назад», сворачивание и возврат, перезапуск и сохранение.
5. Медиа в папке telegram-media: существующая иконка игры 150x150 PNG и существующая обложка 640x360 PNG. Используй их, если BotFather запросит эти размеры. Для другого размера следуй актуальной подсказке BotFather.

GITHUB PAGES
У этой сборки index.wasm весит около 38 МБ. Веб-интерфейс GitHub принимает отдельные файлы только до 25 MiB, поэтому загрузка всех файлов через браузер, как в исходном гайде, не подойдёт.
Для GitHub Pages используй GitHub Desktop или обычный Git: файл WASM помещается в лимит Git 100 MiB.
Вариант с GitHub Desktop:
- Создай локальный репозиторий obby-smash-rush и скопируй содержимое распакованного Web-билда в его корень.
- Сделай Commit и Publish repository. Для GitHub Free репозиторий Pages должен быть публичным.
- В репозитории открой Settings → Pages. Для публикации из ветки выбери main и корневую папку.
- После успешного развёртывания открой выданную ссылку. Обычно адрес проекта выглядит как https://USERNAME.github.io/obby-smash-rush/.
- Эту ссылку затем укажи в BotFather. Развёртывание не обязано завершиться за минуту; дождись успешного статуса публикации.
На первом этапе этот вариант подходит для тестирования статической игры. Хостинг имеет ограничения и не даёт гарантии будущего трафика или дохода.

СОХРАНЕНИЯ
Прогресс локальный: localStorage текущего браузера/Telegram WebView и текущего домена, ключ obby_smash_rush_tg_save_v1.
Смена домена, очистка данных и использование другого устройства не переносят прогресс автоматически. Переноса с CrazyGames, GameDistribution и GameMonetize нет.
Авторизация и облачная синхронизация не подключены. В этой версии клиентские Telegram-данные не используются как подтверждение личности или оплаты.

РЕКЛАМА И STARS
Сейчас реклама, рекламные награды и покупки за Stars отключены. Нет SDK игровых порталов и запросов к их рекламным сетям.
Для Adsgram или другой сети Telegram Mini Apps нужен ID рекламного блока из её кабинета и отдельная проверка реального показа.
Для продажи цифровых товаров за Telegram Stars нужен сервер/бот: создание счёта XTR, обработка pre_checkout_query и successful_payment, проверка данных и выдача покупки с защитой от повторного начисления.
Статический HTML сам по себе не подтверждает оплату. Токен BotFather не требуется для текущей клиентской сборки и не должен записываться в HTML.
Публикация мини-приложения сама по себе не создаёт поток игроков. Правила Telegram и выбранной рекламной сети продолжают действовать.

ИСХОДНИКИ
Импортируй project.godot в Godot 4.5.1. Пресет: Web - Telegram. Для полного Web-экспорта установи соответствующие шаблоны Godot.
Веб-оболочка: web/mobile_shell.html; адаптер: web/telegram_bridge.js; информация об экране: web/mobile_bridge.js. При изменении адаптера синхронизируй его inline-код в HTML-оболочке.
Настройки viewport и отступов обрабатываются отдельно от рекламных SDK. Высота canvas управляется оболочкой, canvas_resize_policy=0.
Тесты этой версии: tests/telegram_bridge.test.cjs, tests/telegram_native.gd, tests/web_export.test.cjs. Тесты старых платформ относятся к истории проекта.

Предел проверки: браузер и подставной Telegram API; реальный запуск внутри клиента Telegram на физическом телефоне после публикации ещё нужно проверить.
